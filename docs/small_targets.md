# ARD-MAV 小目标方法与实验记录

当前全局／局部 YOLO26n 的数据、配置与启动命令见[训练目录说明](../README.md)。
以下 P2 部分记录早先的实验方案；训练入口现在默认选择全局模型，运行历史 P2 时需显式指定配置。

配置：[configs/train_p2_50.yaml](../configs/train_p2_50.yaml)。训练入口为
`scripts/train.py`，复用现有训练循环。
所有启动命令均由你手动执行。

## 本次采用的方法

1. **官方 P2 检测层。** `model=yolo26n-p2.yaml` 对应官方的
   [yolo26-p2.yaml](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/models/26/yolo26-p2.yaml)，
   使用 nano 的 `n` 缩放。检测层从 P3/P4/P5 扩展为 P2/P3/P4/P5，步长为 4/8/16/32。
   输入 640 时，最细特征图由 80×80 变为 160×160，更密的预测位置有利于覆盖微小目标。
   代价是计算量、显存和推理耗时增加。官方配置给出的 80 类 nano 模型参考计算量由约 6.1
   增至 9.5 GFLOPs；你的单类别模型数值会不同。

2. **保留 YOLO26 内置的 STAL 和 Progressive Loss。** STAL 在训练标签分配时扩大极小框的候选区域，
   增加可用的正样本位置；不会修改磁盘上的标签，也不是推理时把框放大。
   这两项在上一轮使用的 YOLO26 中已经存在，本次不能将其算作新增加的改进。
   没有可填写的 `stal: true` 参数。来源：[官方 YOLO26 说明](https://docs.ultralytics.com/models/yolo26)
   和[维护者对 STAL 的解释](https://github.com/ultralytics/ultralytics/issues/23324)。

3. **减弱缩小增强。** `mosaic` 从默认 1.0 改为 0.5，`scale` 从 0.5 改为 0.2，
   最后 10 轮关闭 mosaic。按
   [官方增强定义](https://docs.ultralytics.com/guides/yolo-data-augmentation/#scale-scale)，
   `scale=0.2` 的随机缩放因子为 0.8–1.2，减少原本只有数像素的目标被进一步缩小的机会。
   这组取值是针对 ARD-MAV 的实验选择，官方没有保证它一定优于强增强；减弱增强也可能降低泛化能力。
   `mixup=0` 和 `copy_paste=0` 继续使用原配置。

4. **明确优化器及学习率配方。** `MuSGD`、`lr0=0.0054`、`lrf=0.04952`、
   `momentum=0.94676` 和 `weight_decay=0.00064` 来自本地官方 `yolo26n.pt` 的 `train_args`，
   与[官方 YOLO26 nano 配方](https://docs.ultralytics.com/guides/yolo26-training-recipe)一致。
   相比上一轮自动选择的初始学习率 0.01，这次起始学习率较低；为新增层保留 3 轮预热。
   这是训练配置调整，不能保证解决上一轮验证分类损失异常。

P2 实验原计划保持 `imgsz=640`、`batch=16`，重新训练 50 轮；该配置后来已调整为 `epochs=100`、
`patience=50`。当前全局／局部新配置分别为 50 轮。
结构变化通过 `resume=false` 开始新实验；官方 `yolo26n.pt` 仅为形状匹配的层提供初始化，新增 P2
分支和不匹配的层正常随机初始化。[官方说明](https://docs.ultralytics.com/models/yolo26#supported-tasks-and-modes)
明确指出 P2 只有架构 YAML，没有官方 `yolo26n-p2.pt` 权重。

## 其他能帮助小目标检测的方法

- **增加输入分辨率。** 直接保留更多像素，但增加计算量与显存。本轮按你之前的要求使用 640。
- **原分辨率切片训练、切片推理。** 将原图分块后再输入 640，可避免把整张 1920×1080 图像缩小到
  640 时损失大量细节。训练切片必须同步转换标签，保留背景块，并维持按视频划分。
  [SAHI 论文](https://arxiv.org/abs/2202.06934)讨论切片辅助微调与推理；
  [官方 SAHI 指南](https://docs.ultralytics.com/guides/sahi-tiled-inference)提供推理接口。
  SAHI 与 STAL 是不同方法，SAHI 不是训练 YAML 中的开关。本轮使用现有整图数据集，切片方案列为下一步对照实验。
- **更大的模型或专门的小目标数据。** 更大模型可能提高特征表达能力，但也增加耗时；目标只有数像素时，
  优先保留图像细节，单纯增加模型规模未必能弥补缩放丢失的信息。

P2 提供更密的特征位置，不能恢复缩放时已经丢失的图像内容。本轮是组合实验，不能仅凭最终提升
就断言全部增益来自 P2；需要相同数据划分下的逐项对照才能确定各项贡献。

## 手动启动

先确认旧训练已经退出。使用已有的 `yolo` 环境，进入统一的 `ARD-MAV` 目录：

```bash
conda activate yolo
cd /home/ake/SJTU/graduation-project/ultralytics/ARD-MAV

# 仅预览配置
python scripts/train.py --config configs/train_p2_50.yaml --dry-run

# 显式启动历史 P2 配置；实际训练轮数以配置文件为准
python scripts/train.py --config configs/train_p2_50.yaml
```

结果目录为 `runs/yolo26n_p2_ard_mav_50e/`；重复运行会自动递增目录名。
每轮保存 `weights/last.pt`，验证效果达到最佳时更新 `weights/best.pt`，同时额外保留周期快照。
如果发生显存不足，在启动命令末尾追加 `batch=8`，无需修改输入尺寸。

## 如何比较结果

沿用当前 train/val/test 视频划分，首先比较 `best.pt` 的召回率和 mAP50–95，检查验证分类损失是否
仍出现大幅飙升，再用保留的测试集评估泛化。上一轮验证集最佳点是第 12 轮：召回率 28.667%、
mAP50 30.856%、mAP50–95 13.292%。每次比较使用相同的输入尺寸和评估方式，并记录实际 batch。
训练批次上报的损失值降低，不足以单独证明小目标检测精度提高。

## ARD-MAV 官方训练与使用方式（2026-10-24 核对）

[官方 GLAD 仓库](https://github.com/WindyLab/Global-Local-MAV-Detection)使用全局 YOLOv5、局部 YOLOv5
和外观分类器，并结合运动信息。发布版数据为 60 个视频、107,497 帧；45 个视频随机按约 5:1 用于
训练/验证，另外 15 个测试视频的编号与当前 `prepare.yaml` 一致。官方没有公布完整训练/验证视频名单或随机种子，
因此当前 seed 0 划分只是遵循其比例，并非已经复现原论文划分。

[论文第 V 节](https://arxiv.org/html/2312.11008v1#S5)给出的检测器设置为 YOLOv5s、输入 640、
Adam、初始学习率 0.01、momentum 0.937、batch 32、150 轮。局部检测器用目标中心附近的
320×320 原图裁剪训练。分类器使用 32×32 图块，Adam、学习率 0.001、batch 64、100 轮。
这些是旧 YOLOv5 的复现设置，不能将其学习率直接视为 YOLO26 的最优值。

论文表 IV 中，整帧 640 的 YOLOv5s 召回率为 0.20，完整 GLAD 为 0.82。
这两项在官方测试集上测得；论文 AP 使用 IoU 0.5 的 11 点插值，与当前 Ultralytics 验证集 mAP50/mAP50–95
的计算和数据范围不同，不能直接横向比较。局部检测、运动信息和搜索策略是完整系统的一部分。

官方仓库提供示例和权重，没有完整的一键训练配置；README 仍声明完整 Kalman 滤波及自适应搜索等代码待发布。
不能把运行其公开 demo 等同于严格复现完整论文。

## 保持输入 640 时的改进优先级

1. **原图裁剪训练与切片推理。** 将原始图像划分为 320 或 640 的局部区域，再送入网络，保留目标像素。
   这是基于官方局部检测思路提出的实验方案，尚未在本项目验证增益。需同步变换和裁剪标签、保留背景块，
   先按视频/来源组划分再切片。验证和测试用固定网格或历史预测选择区域，不能用真值框确定目标所在裁剪。
   推理需将坐标映射回整图并合并重叠框；官方 [SAHI 指南](https://docs.ultralytics.com/guides/sahi-tiled-inference/)
   提供切片推理接口，多块推理会增加整帧处理开销。
2. **视频中的全局搜索与局部跟随。** 参考 GLAD，首次全图找目标，随后根据历史检测/运动预测选 ROI；
   漏检时扩大区域并定期全局重检。运动补偿和帧差可作为进一步扩展，需要单独实现和视频评估。
3. **在同一数据版本上做单因素对照。** P2/STAL 仍是候选手段；P2 不能恢复缩小前丢失的细节。
   比较普通 YOLO26n 与 P2 时保持数据、优化器和增强一致，再评估是否需要更大的 s 模型。
   当前 50 轮文件名对应的配置实际已是 `epochs=100`，实验记录应以各次 `args.yaml` 为准。

## 目标相对更大的空对空候选数据集

### 优先：UAVfly

- [作者论文](https://www.nature.com/articles/s41598-024-53181-2)明确采用机载相机空对空采集，
  描述了 10,281 张图像，未刻意侧重微小目标。原论文 YOLOv5s 基线 mAP50 为 93.6%；
  但采用随机 7:3 的训练/验证划分，不能保证按视频独立划分后仍有相同成绩。
- [作者数据仓库](https://github.com/lucien22588/UAVfly)的 `Annotations/*.txt` 抽查符合 YOLO
  归一化中心坐标格式，仍需整理目录和划分。
- 本次按仓库树全量核对文件名：23,200 个 JPEG、9,661 个标签，完整配对 9,661 个；另外 13,539 张图没有
  对应标签，不能自动当作背景。核对的仓库树 SHA 为 `1f7ec40d0f80e0a558b92537998c718753e87c64`，
  这组数量反映公开仓库快照，和论文描述的发布数量不同。
- 对 9 段有标签序列各取首、中、末帧，共 27 个样本；按 16:9 图像等比缩放至宽 640 的内容区域估算，
  框宽/高中位数约 **124.83×34.17 像素**，长边约 52.33–297.00 像素。
  这是固定位置抽样，不是全量尺寸统计；本次下载核看的 3 张图均为 1920×1080，和论文所述分辨率存在版本差异。
  与本地 ARD-MAV 缩放后约几像素的目标相比，这些已核对样本更适合直接 YOLO 检测。
- 建议先使用有标签的配对数据，按 `DJI_0004` 等原视频编号分组，并检查跨组重叠；不要随机打散连续帧。

### 备选：MIDGARD

[官方项目页](https://mrs.fel.cvut.cz/midgard)面向无人机对无人机检测与定位，包含室内外场景，
官网各场景条目合计约 8,800 帧。提供彩色 PNG 和逐帧 CSV 框，CSV 含 `N,X,Y,W,H,D,R`，
其中 X/Y 是左上角像素坐标，需要转成 YOLO 标签并裁剪越界框。

[Det-Fly 作者的实验论文第 V-D 节](https://shiyuzhao.westlake.edu.cn/2020IEEEye.pdf)指出 MIDGARD
目标距离小于约 20 米、标注相对较松，并报告 YOLOv3 的 AP 为 87.7%。这支持其作为近距离较易检测的候选；
本次尚未取得全量标签，不能给出与 ARD-MAV 使用同一口径的尺寸分布。官网可访问，下载服务本次未成功验证。

### 补充评测：UAV-Eagle

[作者仓库](https://github.com/larics/UAV-Eagle)提供 510 张 Eagle 四旋翼图片和 YOLO 格式标签，
适合补充空对空检测与跨机型评测。数量小，不建议单独作为主训练集；未查到全量目标尺寸统计，
因此不将它视为已证实“大目标占比更高”的主要候选。

### 暂不作为降低小目标难度的首选：Det-Fly

[官方仓库](https://github.com/Jake-WU/Det-Fly)提供约 13,000 张真实空对空图片及标注，
但作者明确强调其小目标挑战。它适合作为后续复杂场景对照，不能仅凭图像分辨率高就认定对 YOLO 更容易。

目前优先建议以 **UAVfly 的完整配对数据**建立 YOLO26n、输入 640 的独立视频划分基线，
保留 ARD-MAV 的独立测试视频评估微小目标泛化。若继续以 ARD-MAV 为主，优先验证裁剪/切片及视频 ROI，
再评估模型结构的收益。本次仅核对资料和少量样本，没有下载完整候选数据集或启动训练。
